# 下一轮实验与算法选择：独立评估

日期：2026-11-18。基线提交：`19f5bf6fb53ffd8a51cd02fcf4045a245c639810`。本文件回应外部 AI 建议，结论基于本地原始 NPZ、公开逐组结果及代码复核。

## 判断

建议保留 A1 为底座，先检验一个有严格成本上限的单次换页候选，同时补齐正式数据上的 Dense BF16 / Dense KV4 数值参考基线。暂不扩大 A3 的算法家族或投入 RTL。有限换页仍在优化覆盖缺口，并未从理论上解决覆盖与输出误差不一致的问题；它的价值需要独立质量结果证明。

## 对首轮结论的复核

- p=0.8、20%：A3 的 pooled 相对误差 P95 改善约 2.45%，绝对误差 P95 完全持平；相对误差 P99 反而略升。拆到两个 Prompt，只有第一个的相对 P95 改善，第二个略差。这个“正例”尚不稳定。
- p=0.9、10%：相对误差 P95 恶化约 4.37%，绝对误差 P95 也恶化；去掉 L0 后相对 P95 仍恶化约 5%。不能用删除 L0 来解释或修复该现象。L0 如要采用 Dense 保护，必须单独标记、给全部方法同样配置并计费。
- p=0.8、20%：A1 达标门控 274/384，重组旧 Trace 结果时，可省 20.9188% 的动态 Gain 评估数，pooled 相对 P95/P99 和平均缺口维持原值。但其中 26 条达标 Trace 的 A1/A3 选页集合不同；没有逐条输出保持不变的保证。
- 门控节省尚未扣除 A1 覆盖求和与门控本身的成本；不能把 Gain 评估节省等同于完整 Selector 或系统加速。

## 原始 NPZ：预算与换页空间诊断

固定 δ=0.01、最多一次交换；保护页不得换出；换出为 A1 排序末端的 4 个非保护选中页，换入为排序最前的 8 个未选页。每对交换必须严格降低原始目标下的缺口，并满足相对初始 A1 覆盖的高覆盖 Head 约束。这里仅计算静态覆盖可行性，没有据此声称换页后的输出误差或检索准确率改善。

| 目标/预算 | A1未达标Trace | 含单Head不可达目标的Trace | 有改善的4×8交换 | 单次交换降低总缺口 |
|---|---:|---:|---:|---:|
| p=0.8, 20% | 110 | 100 | 103 | 0.4324% |
| p=0.9, 10% | 199 | 191 | 144 | 0.1918% |

单 Head 必要下界 sum_h max(p-U_h,0) 分别占 A1 总缺口的 82.34% 和 91.51%。这部分缺口在同预算下任何选页集合都无法消除；其余部分也不保证能够同时消除。不能把单 Head 上界误当成联合可行性证明。

这个现象并非只由 L0 决定：去掉 L0 后，必要下界仍占缺口的 73.17%、87.41%；未达标 Trace 中含不可达 Head 的数量分别为 38/47、127/135。分层明细见 `layer_headroom_summary.json`。这些是覆盖目标的诊断，不排除少数关键 Head 的小幅改变带来检索收益。

作为候选截断诊断，另枚举了相同 δ 约束下的全部单次换出/换入配对。4×8 池分别取得全单次交换可实现总收益的约 60.52%、62.53%；全部配对有改善的 Trace 分别为 108、152 条。该全扫描仅离线解释候选限制，不进入在线方案。小缺口改善仍可能保护关键检索，但不支持预设明显质量收益。

逐 Head 的 U、A1 覆盖、U−C_A1 已导出至 `results/pilot_16k_next_step_diagnostics_20261118/headroom_per_trace.jsonl`，共 768 条配置记录。原始两条 Prompt 只用于探索，不作为校准集或独立测试集的证据。

## 可行性折扣应怎样解释

对所有合法集合 S（包含保护且 |S|≤B），都有 C_h(S)≤U_h(B)，因此：

$$\min(p,C_h(S))=\min(\min(p,U_h(B)),C_h(S)).$$

所以 α=1 的目标函数在整个合法集合空间与原目标完全相同，合法加页的边际收益也相同。它是正确性对照，不是新的收益机制。实现时仍需核对浮点容差、并列排序与早停补页，不能把数值/控制流差异算作收益。

α<1 会真正改变目标，且不只降低不可达 Head 的目标，也可能降低原本可达但接近上限的 Head 的目标。它应称为按可达上界调整目标的消融；所有质量指标继续按原始 p 评价。计算 U 需要逐 Head Top-B 及其存储/比较成本，不能仅计 A3 随后的 Gain 次数，因此先作为机制诊断，暂不作为低开销主候选。

## 下一轮建议顺序

1. **离线质量重放**：保留 A1、A3、A3-B(b=8)，显式增加“先 A1 门控、未达标再跑 A3”的控制，以及“先 A1、至多一次有限交换”的候选。先跑两个重点配置，再在旧 Trace 的完整 3×3 网格检查副作用。门控和交换的增量分别对照，不能混作同一收益。
2. **冻结一个换页规则**：主配置 δ=0.01、最多一次、4×8 候选；δ=0 只作保护约束诊断，δ=0.02 和最多两次分开做敏感性，不马上把所有旋钮组合扩成搜索。两次交换的约束始终参照初始 A1。按缺口收益降序、换入 ID 升序、换出 ID 升序处理并列，预算与保护完全不变。
3. **补正式量化基线**：在官方 RULER v1 Multi-Key/Multi-Value 任务上固定版本、数据、Qwen Tokenizer、模板、种子和解码规则。Dense BF16 与 Dense KV4 数值参考仅改变量化路径，Prefill/Decode 后端和算术精度保持一致；若量化本身明显损害检索，先处理量化问题再评价稀疏选择。
4. **校准后一次性测试**：建议先用每子任务 8 个提示做工程验收；正式起步每子任务 32 个校准、128 个独立测试提示，三个 Multi-Key 加一个 Multi-Value 共 512 个测试提示。实际样本量应在查看测试结果前，按最小有意义收益与配对不一致率固定；若要证明很小的精度差，512 个总样本未必够。按原始检索实例划分，旧两个提示不参与调参或显著性证明。
5. **真实闭环**：测试 Dense BF16、Dense KV4 数值参考、A1 与校准后冻结的一个候选。全部方法用相同的全层/Group 稀疏配置、预算、保护和 EOS/输出长度策略，生成完整答案；精确全 QK 决策标记为 Oracle 闭环精度。32K、7:1 GQA、实际摘要与 RTL 在独立质量收益可信后依次推进。

校准/测试必须使用不重叠的检索实例与随机种子，并保存最终输入文件的校验值。正式 RULER 的 16K 长度约定包含输入和预留生成长度，还应计入模型模板开销；不能直接把 Pilot 的 16,384 输入再加输出当成完全相同的设置。`max_new_tokens` 计数也要包含 Prefill 产生的首个 token。长度定义可复核[官方生成器](https://github.com/NVIDIA/RULER/blob/main/scripts/data/synthetic/niah.py)。

## 三个容易遗漏的评价边界

**首个答案 token。** 当前 `capture_sample` 从完整 Dense Prefill 得到第一个生成 token，然后才记录后续 Decode。旧 NPZ 不包含产生第一个答案 token 的检索查询。主实验可继续沿用 Dense Prefill + Sparse Decode，但必须说明这个边界；若诊断首个答案的选择器影响，可单独采用 Prefill 到最后一个提示 token 前、再按 Decode 处理该 token 的协议，所有方法一致并另表报告。

**官方分数与完整正确率。** 官方 RULER v1 NIAH 评分按每条提示中匹配到的正确值比例计分；Multi-Value 的部分正确可以得分。“四个值都正确”的提示级正确率应额外报告，不能替代或冒充官方分数。官方配置有三个 Multi-Key 变体及一个 Multi-Value 任务；采用哪一版本和提交必须固定。

官方源码：[任务配置](https://github.com/NVIDIA/RULER/blob/main/scripts/synthetic.yaml)、[评价函数](https://github.com/NVIDIA/RULER/blob/main/scripts/eval/synthetic/constants.py)。[官方 README](https://github.com/NVIDIA/RULER/blob/main/README.md) 现已区分 v1/v2 新流水线，实施时需明确采用的 v1 提交，而非混用版本。

**关键页与误差参照。** Multi-Value 要标记全部正确值及对应 key–value 关联片段，Tokenize 后记录跨页范围；官方旧生成器的单个 `token_position_answer` 只定位第一个答案，不能用于四值全召回。固定 Dense KV4 轨迹上的误差重放，与每个方法自行生成的任务结果分别评价；各方法轨迹分叉后，不得直接用旧 Dense 的 Q/K/V 当同一状态的误差真值。

## 如何计费及判断是否值得继续

- 当前 `selection.py` 的计时包含每轮重排 W 基线、clip/change 指标、批内首次达标审计等工作。这些不是在线 Selector 的必要工作。下一轮应分别测在线选择、离线审计和共同评分路径，固定线程、预热/重复并报告计时分布。
- 主候选至少记：Top-(B′+8) 构建/比较，A1 覆盖累计，门控比较，实际候选对数、Head 贡献计算/保护比较、接受交换后的更新、第二轮重建（若有）及状态存储。每轮最多 32 对不等于总开销只有 32 次。
- 全部换页都不能超过 A1 的平均保留 Mass 最优值；应报告平均 Mass 损失和每个 Head 的覆盖/误差变化。δ 对初始已达标 Head 的覆盖有约束，但没有 Value/输出误差的保证，初始未达标 Head 也可能被进一步牺牲。
- 绝对和相对误差均给 P95/P99，并按层和 Prompt 拆分；有条件时补输出投影后的误差。任务主表报告官方分数、完整正确率、全部 gold 片段/页召回。
- 在看测试结果前固定质量主指标、最小有意义改善、容许退化和选择开销上限。按 Prompt 成簇配对重采样，并按任务分层；层、步和 Head 不能当成独立 Prompt。仅覆盖缺口改善不足以宣称检索或输出质量改善。
- 若独立测试质量与成本同时成立，继续扩模型/长度与实际 Metadata；若差异仍停留在覆盖缺口，保留 A1，优先研究等总字节下的摘要质量。当前分析未放行 Gate 1。
